\# PetWhale 详细设计方案



\## 1. 项目概述



\*\*项目名称：PetWhale\*\*



建议定位：



> \*\*PetWhale 是一个面向 AI Agent 的可插拔视觉伴侣框架，将 Agent 的运行状态转换为可视化角色行为，并支持 DeepSeek Harness、Telos 以及未来其他 Agent Runtime。\*\*



它不是一个 Live2D 封装库，也不是 Telos 专属插件。



整体关系：



```text

Agent Runtime

&#x20;    │

&#x20;    │ 状态 / 事件

&#x20;    ▼

┌────────────────────┐

│     PetWhale       │

│ Companion Runtime  │

└─────────┬──────────┘

&#x20;         │

&#x20;         │ semantic state

&#x20;         ▼

┌────────────────────┐

│     Renderer       │

├────────────────────┤

│ Orb                │

│ Sprite             │

│ Live2D             │

│ Rive / VRM / 3D... │

└────────────────────┘

&#x20;         │

&#x20;         ▼

&#x20;     Visual Pet

```



第一阶段重点支持：



```text

DeepSeek Harness Web  ✅

Telos Desktop         ✅



Orb Renderer          ✅ MVP

Sprite Renderer       Planned

Live2D Renderer       Planned

```

\# 2. 项目目标



PetWhale 要解决的核心问题不是：



> “怎么在页面里显示一个 Live2D。”



而是：



> \*\*如何建立 Agent Runtime 和视觉角色之间稳定、通用、可扩展的语义层。\*\*



例如 Agent 底层可能产生：



```text

assistant/chunk

tool/call

tool/result

turn/start

turn/end

session/running

```



PetWhale 不应该让 Renderer 理解这些。



PetWhale 应该把它们统一转换成：



```text

idle

thinking

answering

working

waiting

success

error

sleeping

```



于是：



```text

DeepSeek Harness

&#x20;      │

&#x20;      ▼

&#x20; DSH Adapter

&#x20;      │

&#x20;      ▼

&#x20;  PetWhale

&#x20;      │

&#x20;      ▼

&#x20;  "working"

&#x20;      │

&#x20;      ├── Orb → 高速旋转

&#x20;      ├── Sprite → 敲键盘

&#x20;      └── Live2D → Working Motion

```



这样 Agent 和角色彻底解耦。



\---



\# 3. 非目标



PetWhale V1 不负责：



```text

Agent 推理

Prompt 管理
```

\# 8. CompanionState



定义角色的持续状态：



```ts

export type CompanionState =

&#x20; | 'idle'

&#x20; | 'thinking'

&#x20; | 'answering'

&#x20; | 'working'

&#x20; | 'waiting'

&#x20; | 'success'

&#x20; | 'error'

&#x20; | 'sleeping'

```



含义：



| State     | 含义                       |

| --------- | ------------------------ |

| idle      | 没有运行任务                   |

| thinking  | 模型正在 reasoning           |

| answering | 模型正在生成最终输出               |

| working   | Tool / shell / edit 等执行中 |

| waiting   | 等待用户确认或输入                |

| success   | 刚完成任务                    |

| error     | 刚发生错误                    |

| sleeping  | 长时间 idle                 |

\# 14. Behavior Scheduler



Agent 状态可能变化非常快：



```text

thinking

working

thinking

working

answering

working

answering

idle

```



如果全部实时推给 Live2D：



```text

角色会像接触不良。

```



因此需要 Scheduler。



建议：



```ts

export interface BehaviorPolicy {

&#x20; transitionDebounceMs: number



&#x20; successHoldMs: number



&#x20; errorHoldMs: number



&#x20; sleepAfterMs: number



&#x20; minimumStateDurationMs: number

}

```



默认：



```text

transition debounce    120ms



success hold           1800ms

error hold             2200ms



sleep after            5min

```



这些以后都可以配置。

\# 15. 状态优先级



建议：



```text

error

&#x20; ↓

waiting

&#x20; ↓

working

&#x20; ↓

answering

&#x20; ↓

thinking

&#x20; ↓

idle

&#x20; ↓

sleeping

```



`success` 和 `error` 属于 transient state。



例如：



```text

working

&#x20;  ↓

任务完成

&#x20;  ↓

success

&#x20;  ↓ 约 1.8 秒

idle

```



而不是：



```text

success

```



永远保持到下一轮。

\# 17. DSH Plugin Entry



建议：



```ts

export const inject = \[

&#x20; 'slots',

&#x20; 'sessions'

]



export function apply(ctx: ClientContext): void {

&#x20; // setup source



&#x20; ctx.slots.inject(

&#x20;   'shell.overlay',

&#x20;   () =>

&#x20;     ctx.slots.register(

&#x20;       {

&#x20;         name: 'shell.overlay',

&#x20;         id: 'petwhale',

&#x20;         order: 50

&#x20;       },

&#x20;       PetWhaleOverlay

&#x20;     )

&#x20; )

}

```



必须使用：



```ts

ctx.slots.inject(...)

```



而不是假设 ui-layout 已经加载然后直接 register。



DSH 当前官方 client 开发规则明确要求第三方注册其他插件声明的 slot 时使用 `ctx.slots.inject()`，这样 declaration 尚未存在时可以等待，layout 重建后也能够自动重新挂载。

\# 19. DSH State Adapter



第一阶段不需要去订阅内部 Host 原始 SessionEvent。



直接利用 DSH 对 Client 提供的正式 snapshot API。



当前 `ConversationSnapshot` 已提供：



```text

running

partial

runningCalls

pending

promptError

lastAgentError

```



Session list 还提供：



```text

running

pendingInteraction

completed

blank

```



因此可以写：



```ts

function resolveState(

&#x20; session: ConversationSnapshot

): CompanionState {



&#x20; if (session.promptError)

&#x20;   return 'error'



&#x20; if (session.lastAgentError)

&#x20;   return 'error'



&#x20; if (session.pending.length > 0)

&#x20;   return 'waiting'



&#x20; if (session.runningCalls.length > 0)

&#x20;   return 'working'



&#x20; if (hasReasoning(session.partial))

&#x20;   return 'thinking'



&#x20; if (hasAnswer(session.partial))

&#x20;   return 'answering'



&#x20; if (session.running)

&#x20;   return 'thinking'



&#x20; return 'idle'

}

```

\# 22. Telos 集成边界


\# 24. DSH 特殊构建机制



这是 PetWhale 最大的工程挑战之一。



DSH Client Plugin 不是普通 Vite bundle。



最终产物类似：



```js

window.\_\_ModuleLoader\_\_.load({

&#x20; id: '@petwhale/dsh',



&#x20; factory(require) {

&#x20;   // plugin bundle

&#x20; }

})

```



官方 shared tsdown preset 还负责：



```text

React external

Cordis external

DSH platform modules external



普通 dependency inline



CSS module injection



source map



plugin unload cleanup



cross-plugin value import 检查

```



所以 PetWhale V1 推荐：



```text

vendor/

└── deepseek-harness/

```



作为固定 Git Submodule。



CI 构建 `@petwhale/dsh` 时复用当前 DSH preset。



发布的 npm package 直接包含：



```text

lib/client.js

```



最终用户不需要这个 submodule。

\# 50. 最重要的架构规则



PetWhale 项目从第一天就建议写进 `ARCHITECTURE.md`：



\### Rule 1



```text

Core does not know Hosts.

```



`@petwhale/core` 不允许：



```ts

import '@deepseek-ai/...'

```



\---



\### Rule 2



```text

Core does not know Renderers.

```



Core 不能：



```ts

if (renderer === 'live2d')

```



\---



\### Rule 3



```text

Hosts emit semantics, not visuals.

```



DSH Adapter 输出：



```text

working

```



不能输出：



```text

playMotion("Typing01")

```



\---



\### Rule 4



```text

Renderers consume semantics,

not Agent events.

```



Live2D 不应该知道：



```text

tool/call

assistant/chunk

```



\---



\### Rule 5



```text

PetWhale never owns Agent business state.

```



Session 的真实状态永远属于 Agent Runtime。



PetWhale 只是 Projection。



\---



\### Rule 6



```text

One host package should work

across compatible hosts.

```



目标始终是：



```text

@petwhale/dsh



DeepSeek Harness ✅

Telos            ✅

```



而不是：



```text

@petwhale/dsh

@petwhale/telos

```



除非未来 Telos 出现真正独立于 DSH 的 Companion API。
